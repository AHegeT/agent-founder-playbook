# From Demo to Production: Taking What You Built From One User to Many

## Session Overview

It worked perfectly when it was just you testing it. Now five people are using it — then fifty. What breaks first, what security holes open up, and what should've been designed in from day one?

This roundtable is about the gap between "works for me" and "works for everyone." We'll get practical about the challenges of taking something you built once and making it scalable and ready for multiple users.

## What We'll Discuss

- **What Breaks at Scale** — Things that were invisible with one user: race conditions, shared state or context bleeding between users, rate limits you never hit solo, costs that multiply per-seat instead of staying flat.
- **Security** — Auth and access control once it's not just you, data isolation between users, secrets/API key management, and prompt injection risk when inputs come from people you don't control.
- **Design Checklist** — The basics to build in early: statelessness, per-user logging/observability, multi-tenant data design, config/session handling — so scaling later doesn't mean a rewrite.

## Who Should Attend

This session is perfect for:
- Builders whose tool works great for them but hasn't been opened up to others
- Anyone about to onboard their first real users
- Operators who've been burned by a "just add users" request that turned into a rewrite

## Format

This is an interactive roundtable discussion where participants share experiences and learn from each other. Bring the moment your "it's just for me" tool had to become "it's for my team."
